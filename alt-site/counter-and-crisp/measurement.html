The desk · Measurement

Measurement before optimization.

The counter runs on day one so the campaign ledger has somewhere honest to come from. It is privacy-preserving by design, and the ledger stays empty until authorized first-party reports fill it — a measured zero beats a manufactured number.

The five defined events

The brief refers to "the five defined events" without enumerating them in this session's copy, so the working taxonomy below is defined here and flagged for confirmation (FLG-005). Payload fields: e event, p page path (no query strings), a observed ASIN where relevant, t timestamp.

EventTriggerFieldsNotes
sessionFirst event of a browsing session (sessionStorage flag)e, p, tFires once per browser session; no cookie, no id.
page_viewAny page loade, p, tPath only — no query strings, no referrer.
product_impressionA product card or row first enters the viewport (IntersectionObserver)e, p, a, ta = observed ASIN of the product shown.
outbound_clickA sponsored product link is clickede, p, a, tFires before navigation; counts clicks, not outcomes.
guide_viewA guide page loadse, p, tLets the campaign ledger compare guide pull vs product pull.

Privacy note

  • No cookies. Nothing is written to the visitor's cookie jar; session continuity uses sessionStorage and clears when the tab closes.
  • No personal data, no IP capture, no fingerprints. The payload carries an event name, a page path, a product id, and a timestamp. Nothing else.
  • Local-only mode is live. Until an endpoint is deployed, tallies stay in the visitor's own browser (localStorage) and can be exported or deleted by them at any time. Nothing is transmitted anywhere.
  • When the endpoint goes live (FLG-006), it receives only the payload above via navigator.sendBeacon, and its operator must not log IP addresses or user agents. That constraint is part of the contract below.

Self-hosted collect endpoint — contract

GitHub Pages serves static files only, so the endpoint must live elsewhere (a small worker, function, or VPS). The contract is fixed and tiny; deploy it and set <meta name="cc-collect-endpoint"> in the page head to activate delivery.

Cadence & iteration policy

  • Publishing cadence: two question-shaped guides per month plus seasonal edits; every guide joins sitemap.xml and feed.xml automatically at build time.
  • Measure before writing more: after 2–4 weeks of Search Console data (SUG-006), the next topics come from measured queries — the current five titles are declared hypotheses.
  • Measure before automating optimization: no auto-rewrites, no auto-pricing updates, no auto-ranking changes. Optimization proposals enter the suggestion queue like everything else.
  • Reader capture (SG-30): RSS is live (feed.xml); email capture is a proposal (SUG-011), not a dark pattern in waiting.
