Review before anything changes

The suggestion board

Every change this site could make arrives here first, as a choice between named paths. Nothing is implemented until a path is chosen — the statuses below say exactly what is live and what is only proposed.

3 shipped in this build 6 awaiting a choice

How this board works

Each suggestion below is a fork, not a mandate. Read the paths, pick one per card — or none — and only then does anything change. Status labels: “Shipped in this build” means the recommended path is already live and the alternative stays on the table; “Awaiting choice” means nothing has been done; “Needs owner input” means the paths cannot be compared until a question on the Decision Inputs page is answered.

Programme suggestions (buy a review unit, deploy measurement, publishing cadence) live in the Decision Room. The information each choice is waiting on lives on the Decision Inputs page.

Group

Reads like a shop, not like a process

DS-01

Front-page voice: lead with the products

Shipped in this build

The problem. The first screen of a shop should sell the goods, not describe the audit. Verification belongs where a careful reader looks for it, not where an arriving one lands.

Path A — shop-first front page (recommended)

Hero leads with the five picks and buyer questions; the honesty band sits below the products and links through to the methods pages. Shipped in this build.

Effort: Done

Path B — full magazine front page

Rotating feature story, larger imagery, issue-style sections. More editorial presence; more to maintain and more image work.

Effort: 2–3 days

Path C — product grid only

Pure catalogue. Converts the front page into a listing and loses the question-shaped entry points that earn search traffic.

Effort: 1 day

RecommendationPath A. Path B becomes worth it when there is a named author and an imagery budget (DS-04, DS-05).

Before this can be chosen: Nothing.

DS-02

Seasons and topic clusters

Shipped in this build

The problem. A publication reads as alive when its entry points follow the calendar. Clusters also give search engines clear topical neighbourhoods instead of one flat list.

Path A — seasonal cards plus two seasonal guides (recommended)

A “start with the season” band on the front page pointing at question-shaped guides, two of which ship now: hosting season and gifting.

Effort: Done

Path B — a full seasonal hub per quarter

A dedicated page per season with curated picks. More depth, more upkeep, and a risk of thin pages once the season passes.

Effort: 2 days per quarter

RecommendationPath A now; Path B only after measured interest — the ledger and the click counter will show which seasons earn readers.

Before this can be chosen: Nothing to start; measurement to choose the next season (DI-04).

DS-03

What to publish next: the topic engine

Awaiting choice

The problem. The next topic should come from measured queries, not instinct. Until measurement exists, the safest engine is the hypothesis list the brief already names.

Path A — question-shaped long-tail guides (recommended)

Continue the editorial hypotheses: comparison questions, checklists, trade-off guides. Each answers one searchable question and links back to the register.

Effort: 1 guide per fortnight

Path B — head-to-head comparison pages

Higher search volume, harsher competition, and a shape that tempts verdict language this site cannot support without handling the products.

Effort: 2 days each

Path C — recipe-led content

Traffic-friendly but off-register: recipes would imply use of machines this desk has not handled.

Effort: Ongoing

RecommendationPath A until the campaign ledger shows which topics earn clicks (SUG-06). Path C is rejected outright under the non-testing policy (FLG-004).

Before this can be chosen: Analytics live (DI-04) before measuring anything; nothing blocks starting Path A.

Group

Trust: authorship, brand, imagery

DS-04

Authorship: a desk or a person?

Needs owner input

The problem. Google’s site-reputation review weighs stated or implied authorship. A named editor with a short biography is the cheapest trust signal available to a young publication.

Path A — keep the Counterwise desk

Current state. Consistent and honest about the non-testing policy, but anonymous.

Effort: Done

Path B — named author and biography page (recommended when decided)

A real byline with a two-line biography and a contact route. Materially improves trust and policy posture; requires the owner’s identity decision.

Effort: Half a day

RecommendationPath B as soon as the owner answers DI-06.

Before this can be chosen: DI-06 (Q-05).

DS-05

Imagery: abstract art or product photography?

Awaiting choice

The problem. Imagery is the difference between published and generated. It is also the easiest place to accidentally use Amazon’s content outside the licence.

Path A — original abstract art (recommended for now)

Current state: consistent, light, clearly not a product photograph, and containing no third-party content.

Effort: Done

Path B — commissioned product photography

Requires owning or borrowing the units (ties to DI-03). The only imagery that can honestly show a machine in use.

Effort: Unit cost plus 2–3 days

Path C — listing images taken from Amazon

Not recommended: the IP licence limits how Program Content may be reused, and unlicensed listing images are the kind of shortcut this site exists to avoid.

Effort: —

RecommendationPath A now, Path B after DI-03 resolves. Path C rejected.

Before this can be chosen: DI-03 for Path B.

Audience: capture, distribution, findability

DS-06

Reader capture: what should the form do?

Needs owner input

The problem. A form that silently discards input is worse than no form. The current form is deliberately inert and says so on the page.

Path A — honest inert form (current)

Fires the capture_intent event, transmits nothing, and tells the reader so.

Effort: Done

Path B — wire a mailing provider (recommended when chosen)

A provider with a documented data story, consent copy, and one endpoint. Then the form collects for real.

Effort: Half a day

Path C — remove the form

Cleanest surface, but loses the intent signal that is already being counted.

Effort: 1 hour

RecommendationPath B once DI-05 names a provider.

Before this can be chosen: DI-05 (Q-04).

DS-07

Search Console and the domain question

Needs owner input

The problem. Query-level data needs a verified Search Console property. The github.io project path works but is a weak brand home.

Path A — verify the current URL-prefix property (recommended first)

Owner pastes a verification token; the sitemap is already shipped and linked from robots.txt. Fifteen minutes of owner time.

Effort: 15 minutes, owner

Path B — move to a custom domain

Better brand home and cleaner cookie scope; needs a domain purchase and DNS control.

Effort: Half a day plus the domain

RecommendationPath A immediately; Path B as a later brand step.

Before this can be chosen: Owner’s Google account (DI-06).

Machinery: measurement and decisions

DS-08

Link strategy before scaling traffic

Needs owner input

The problem. The supplied short links carry no visible tag. Whether they credit the account at click time is unresolved (FLG-001, FLG-003).

Path A — tagged canonical listing links (current)

Every money link is built from the observed ASIN plus the owner’s tag. Safe, checkable, and enforced by the build gate.

Effort: Done

Path B — run the dashboard test, then decide (recommended before scaling)

Mint one link per product inside the enrolled Associates workflow, click it, and confirm the tracking report. Closes or confirms FLG-001 and FLG-003.

Effort: Under an hour, owner

RecommendationPath A stays the default; do Path B before any paid or scaled distribution.

Before this can be chosen: DI-01 (Q-01, FLG-003).

DS-09

How decisions get made from here

Shipped in this build

The problem. The project promised evidence-based iteration. That needs a place where options are reviewed before anything ships, and a record of what was chosen.

Path A — this board plus the Decision Inputs page (recommended)

Every change arrives as a card with named paths; every open question arrives with a discovery suggestion. Shipped in this build.

Effort: Done

Path B — add a dated decisions log

Each chosen path gets a dated entry with the reason and the evidence. Small overhead, permanent record.

Effort: 1 hour to start

Path C — generate suggestions from measurement

When the ledger has rows, generate review cards from it. Premature until there is data.

Effort: Later

RecommendationPath A now, Path B from the next decision, Path C only after the ledger has real rows.

Before this can be chosen: Nothing.
