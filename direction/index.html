What we know, what we still need, and the paths available — so a person can pick one before any further change is made. Nothing in the “proposed” rows below has been implemented.

Executive summary

The project. Counterwise is an Amazon Associates publication: five kitchen products (three air fryers, two meat thermometers) promoted through question-shaped buying guides, with the tracking ID shopnow047c-20. The site is live on GitHub Pages with a shop-first front page, four published guides, category pages, an RSS feed, and a sitemap.

What was verified on 2026-11-20. All five supplied short links were resolved live; each landed on an official Amazon listing, and every listing was read to capture brand, model number, and observed ASIN (source register: products page). Amazon’s own definition of an ASIN (unique 10-character code, Sell on Amazon) shows the supplied 9-character tokens are not ASINs — so the intended ASIN fields stay blank pending owner confirmation (FLG-001) while the observed destinations are recorded separately. Program Policies (Amazon, updated 2026-04-14), FTC endorsement guidance (FTC), and Google’s rel="sponsored" rules (Google Search Central) were read and are enforced by the pre-publish gate (scripts/check_site.py).

What is deliberately blank. Prices, ratings, review counts, commission rates, traffic, clicks, orders, and revenue. None can be sourced from an authorized, dated first-party report today; each is flagged rather than filled (flags). The campaign ledger starts empty for the same reason.

What is built but not yet provable. Special Links carry the Associates tag and rel="sponsored", one per product, destinations confirmed live — but click/order attribution in the enrolled Associates report is untested (FLG-002). The click layer records all five defined events to a per-device ledger; the site-wide analytics endpoint is provisioned-as-null and needs an owner decision (FLG-006). Search Console verification and reader email capture need owner accounts (FLG-007, FLG-008).

What we recommend next. Path A (measurement) before Path B (content expansion) — details and trade-offs in the chooser below. All paths are proposals; the choice is the owner’s.
