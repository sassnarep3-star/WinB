Choose first

Three paths — pick one before anything is implemented

Each path is a coherent bet. Mixing them is how a site ends up with seasonal guides, no measurement and no byline. The desk recommends Path B first, Path C in parallel: the publication polish is already built, and the measurement endpoint is the only thing standing between instinct and data.

Choose before anything is implemented

Every proposal below carries named options, a recommended one, and a decision gate. Nothing is acted on because it appears on this page — it is acted on when an option is chosen and recorded. That is the whole protocol: read the options, pick a letter, write it down.

Record a choice in one line — “SUG-01: A” — in the repository's COORDINATION.md under this session's row, or as a reply to the session. The next build reads the recorded decision, changes the decisionState line for that proposal, and the page reflects it. Two are already recorded: SUG-05: A and SUG-08: A. Why this register exists at all

Most wrong turns on a project like this are information errors wearing a decision’s clothes: a topic chosen with no query data, a price table pasted from a stale page, a revenue forecast built on commission rates nobody has read from an authorised report. Naming the gap in one table — with the discovery step attached — keeps the decision and the information separate, so the owner can choose the best path with the record open in front of them.
