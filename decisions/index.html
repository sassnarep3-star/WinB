Part one

Suggestions, in the order they should be reviewed

Priority 1 means “do this before writing another word”. Every item states its risk, because a recommendation without a failure mode is marketing.

P1

Buy and document one review unit

Proposed — awaiting owner choice
RecommendationStart with the cheapest of the five. Buy it, photograph the unboxing, publish the receipt.
Why it matters
Every page currently describes listing data and fit. One disclosed bought-and-tested unit converts the whole site from specification summary to review, which is the only durable defence against both Google’s thin-affiliation problem and reader distrust.
Effort
Cost of one unit, 2–3 days
Payoff
Highest of anything on this page
Risk
A single unit does not generalise. Do not let it become “we tested everything”.

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

Path ABuy the cheapest unit now

Spend is small and the content lift is immediate, but one unit only speaks for itself.

Path BRequest a review unit from the two brands

No spend, but a disclosure obligation attaches, and a project with no traffic history may be refused.

Path CKeep the specification-and-fit framing

Zero cost and legally clean, but the site never differentiates from listing summaries.

What you need to decide: A budget decision plus a disclosure preference. Path A needs only the owner’s go-ahead; Path B needs the owner to send the request from a real address (see Q-07).

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

What you need to decide: Dashboard access. This is the single highest-value action on the page and nothing here can perform it without the owner’s login.

P2

Deploy the analytics collector and let it run for 30 days

Source shipped, not deployed
RecommendationDeploy the supplied worker, set one endpoint, and treat the first 30 days as a baseline rather than a scoreboard.
Why it matters
Without measurement the next topic is chosen by instinct — the exact failure mode this project set out to avoid. Thirty days of page_view plus outbound_click is enough to rank the existing guides honestly.
Effort
Half a day, then nothing
Payoff
Turns topic choice into a data question
Risk
Small samples mislead. Do not compute a conversion rate from a dozen clicks.

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

Path ADeploy the supplied self-hosted worker

First-party, privacy-preserving, no third-party cookies; needs a Cloudflare account or equivalent.

Path BPoint ENDPOINT at any existing first-party logger the owner runs

Fastest if such a service exists; schema must accept the five event names unchanged.

Path CShip with the counter off

Nothing is measured and the campaign ledger stays empty; acceptable only if the owner prefers no telemetry at all.

What you need to decide: Whether the owner has a Cloudflare (or similar) account to host the worker, or an existing endpoint to reuse. Everything else is already built.

Effort
1–2 days
Payoff

Risk
The tone must stay practical. A framework with no numbers of its own is still thin.

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

Path AAdd a printable measurement worksheet to the existing capacity guide

Turns a good draft into a genuinely linkable tool; needs one evening of work and a PDF.

Path BLeave the guide as prose

Already published and useful; the worksheet is the part that earns outside links.

What you need to decide: Whether the owner wants downloadable tools on the site at all. Everything needed is already in the published guide’s method.

P3

Publish on a fixed cadence and stop

Proposed — awaiting owner choice
RecommendationOne substantial guide every two weeks, announced in the feed, added to the sitemap automatically. Not daily, not whenever inspiration arrives.
Why it matters
Google treats a burst of near-identical pages as scaled content abuse. A slow, steady, original cadence reads as a publication; a 40-page month reads as a content farm. The build already regenerates the sitemap and feed, so cadence costs nothing but writing.
Effort
Ongoing
Payoff
Compounding
Risk
Miss two cycles and the site looks abandoned. Two weeks is achievable; daily is not.

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

Path AFortnightly, seasonal clusters first

Matches the seasonal calendar this build ships; steady enough to look alive, slow enough to stay original.

Path BMonthly

Safest for quality, slowest to build a body of work.

Path CWeekly

Faster footprint, but every cycle must be genuinely original or it reads as scaled content.

What you need to decide: How much writing time the owner actually has per month. The build cannot make that trade-off.

P4

Standing recommendation

Effort
Restraint
Payoff
Protects the whole site
Risk
Feels slow. It is slow.

What you need to decide: Nothing until the campaign ledger has real rows to argue with.

Why it matters
Seasonal clusters give the publication a reason to exist on a date, not just at a query. But a calendar the owner has not approved becomes work nobody wants. This suggestion exists to get the decision made before more pages are written.
Effort
One review of the calendar below
Payoff
Turns the publishing cadence (SUG-06) into a plan
Risk

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

Path AFull calendar: holiday → gifting → game-day → spring reset → summer grilling

Always something in season; five clusters a year of writing.

Path BHoliday and gifting only, evergreen otherwise

Concentrates effort where intent is highest; quieter mid-year.

Path CDrop seasons, publish evergreen question guides only

Simplest; loses the “why now” reason to revisit.

What you need to decide: Which seasons match the owner’s actual audience. Q-11 collects the answer.

Payoff

P3

Decide the byline: a named author or the desk

Proposed — awaiting owner choice
RecommendationA named author with a two-line biography, or a formal editorial desk with a published policy. Pick one and make the pages consistent with it.
Why it matters
Google’s site-reputation policy weighs stated or implied authorship explicitly, and readers trust a person or an institution — not an anonymous page. The current “Counterwise desk” byline works only while the editorial policy is visible and honoured.
Effort
A decision, then a small copy pass
Payoff
Trust and policy posture
Risk
A named author takes public editorial responsibility. That is the point, and it is a real commitment.

Choose one path before this moves. Nothing here is implemented until a path is picked — review, choose, then build.

Path ANamed author with a real bio

Strongest trust signal; the owner’s name becomes public.

Path BKeep the desk byline, strengthen the editorial policy page

Institutional and private; slightly weaker on the authorship factor.

What you need to decide: Whether the owner wants to publish their identity (Q-05).

Part two

The questions that must be answered before a decision

Each row separates what is known from what is unknown, and names the cheapest way to find out. Rows marked Answered are decisions already made and implemented.

12 questions. 3 answered, 9 still need information.
IDStatusQuestion What is knownWhat is missingHow to find out
Q-01 Blocked Did the five supplied short links come out of the shopnow047c-20 Associates account?
It decides whether referrals are credited at all. The observed targets carry no tag parameter.		 All five resolve to live listings. None of the resolved URLs carries tag=shopnow047c-20. Whether Amazon applies the account tag at click time for links minted inside the dashboard. Generate one short link inside Associates Central while signed in, resolve it, and compare its parameters with the supplied set. Five minutes in the dashboard settles it.
Q-02 Open Which channel is expected to produce the first 100 sessions?
A new project site with no domain authority will not rank for competitive head terms in its first month. The first-traction plan should name a realistic channel rather than assuming search.		 No analytics are live, so current traffic is unmeasured (FLG-007). Any existing audience the owner already has: a list, a social following, a community. Owner inventories channels they can reach today. If the answer is “none”, the plan should be paid-or-pinned distribution and long-tail queries, not a head-term bet.
Q-03 Open Is a review unit obtainable for any of the five products?
Hands-on content is the single biggest differentiator available, and the current pages are legally barred from pretending to it (FLG-004).		 No unit is held. The listing data is thorough enough for specification content only. Whether any brand will supply a unit to a project with no traffic history. Ask the two brands directly. If the answer is no, buy the cheapest unit and document the purchase — a disclosed bought-and-tested unit is still a test.
Q-04 Open Which mailing provider will receive captured addresses?
The capture form currently collects nothing usable (FLG-008). A form that silently discards input is worse than no form.		 The form fires a capture_intent event and does not transmit an address. Provider, consent language, and the lawful basis for storage. Pick a provider with a documented EU/US data story, then wire ENDPOINT and consent copy in one change.
Q-05 Open Who owns the site — a person or a desk?
Google’s site-reputation policy explicitly weighs “stated or implied authorship”, and an unauthored affiliate page with no commercial disclaimer is the example it gives of content likely to attract action.		 Pages currently sign as “The Counterwise desk” with a stated non-testing policy. Whether the owner wants to publish a real byline and take editorial responsibility publicly. Owner decision. A named author with a two-line biography is cheap and materially improves both trust and policy posture.
Q-06 Open Will the site move to a custom domain?
A github.io subpath is a fine host but a weak brand home; it also makes Search Console property setup and cookie scope awkward.		 Current origin is a GitHub Pages project path. Whether a domain will be bought, and who controls DNS. Owner decision, then a CNAME file and a Search Console domain property.
Q-07 Open What is the contact route for corrections?
A publication without a contact route cannot be corrected, and reviewers notice.		 No email address is published. The repository issue tracker is the only route. Whether the owner wants a public address. Create one and publish it, or formalise the issue tracker as the route.
Q-08 Answered Can prices and star ratings be displayed on a static affiliate page?
It determines whether comparison tables can carry prices at all.		 No — not without Amazon serving the link or Creators API / PA API data. The site therefore shows no prices or ratings. — Answered from Participation Requirements §2(b).
Q-09 Answered What disclosure wording must appear?
It is a material-breach risk, not a courtesy.		 Operating Agreement §5 specifies “As an Amazon Associate I earn from qualifying purchases.” The site carries it under the masthead on every page and again in the footer. — Answered from the Operating Agreement.
Q-10 Answered How should outbound product links be marked for search engines?
Unqualified paid links breach Google’s link-spam policy; the fix is a one-attribute change.		 rel="sponsored" for advertisements and paid placements. This site uses rel="sponsored nofollow noopener" on every Amazon link. — Answered from Google Search Central.
Q-11 Open Which seasons should the publishing calendar run on?
This build ships three seasonal clusters (holiday hosting, gifting, weeknight crisping) as a working demonstration of the format. Writing more of them without an approved calendar is how a publication turns into a content farm.		 The format works: a cluster is one lead guide, two or three picks, and a themed slot on the front page. The first three are live. Whether the owner wants seasons to drive the calendar at all, and which seasons match the actual audience (game-day? summer grilling? back-to-school?). One decision in the Decision Room (SUG-09): pick the full calendar, holiday-and-gifting only, or drop seasons entirely. Nothing else is written until then.
Q-12 Open Should the archived competing site trees be deleted once recrawl is confirmed?
Fifty-six superseded pages from earlier sessions are kept, marked noindex and banner-labelled (FLG-011). Keeping them is safe but permanent; deleting them tidies the repository at the cost of losing the in-place record.		 The pages are noindex, nothing in the live navigation links to them, and they remain readable in git history either way. Whether search engines have recrawled and dropped them, and whether the owner wants the working trees preserved as-is. Check Search Console coverage after verification (Q-06/SUG-10), then delete or keep in one commit. No urgency either way.

The pattern in the open questions

Most open items need something only the owner has: dashboard access, a decision about identity or seasons, or money. That is not a research failure — it is the boundary of what a session without account access can settle. Where the answer is a check anyone with the login could do in ten minutes, the question says so and gives the steps.
