Decision room

Suggestions, with a cost and a decision attached

This is the review surface. Every suggestion is a proposal, not a change that has been made. Each one carries what it would take, what it would prove, and what it would cost — so a decision can be made by reading one row instead of commissioning another analysis.

How to use this page

Pick a path, not a feature. The three paths below are coherent complete positions; individual suggestions can be adopted piecemeal, but the site only makes sense as one of the three. Nothing here is implemented beyond the baseline already live — the current build is Path A.

Path A — The honest shop

Live now

Publish only what is verifiable. Label every claim. Show no prices until an authorised data route exists. Small, defensible, slow to grow.

Why it wins: it cannot be penalised for false claims, and it is the only path that can be built entirely from documents.

Why it loses: it will not out-convert a site that shows prices and ratings, because buyers want numbers.

Path B — Open the data taps

Recommended

Apply for Product Advertising API access and use SiteStripe. Show price and availability with the required timestamp and disclaimer. Keep every label. Add measurement.

Why it wins: it converts the site's main disadvantage into its main feature — live data with an auditable trail.

Why it loses: depends on an approval the owner does not control yet.

Path C — Become a test desk

Highest ceiling

Buy units, test them, publish protocols and results. Hire nothing; publish the method. This is the only path that justifies the word "reviewed".

Why it wins: original data is the one thing a competing site cannot copy.

Why it loses: it needs spend and time before the first publishable result.

What to choose, if you only choose once

Path B, in this order. (1) Confirm the Associates account and the tag — that is Q-01 and nothing else matters until it is done. (2) Run the one-link test and confirm a click appears in the report — Q-02. (3) Turn on the event endpoint — Q-05. (4) Apply for API access — Q-13. Everything else on this page is optimisation in front of those four; doing them in a different order is how sites end up with beautiful pages and no data.
